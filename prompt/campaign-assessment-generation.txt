Generate a practical hiring assessment draft for the campaign context.

Prioritize job-relevant scenarios over trivia. Questions should help reviewers
evaluate how candidates reason through realistic work, debugging, tradeoffs,
and implementation decisions.

Return exactly one JSON object with this root shape:

{
  "sections": [
    {
      "title": "Section title",
      "description": "Short optional section description",
      "duration_minutes": 30,
      "weight": 100,
      "sort_order": 10,
      "questions": [
        {
          "type": "long_text",
          "prompt": "Role-specific scenario or work sample",
          "expected_rubric": "Observable qualities expected in a strong answer",
          "points": 10,
          "difficulty": "medium",
          "sort_order": 10
        }
      ]
    }
  ]
}

Strict output rules:
- Root must contain only "sections"; do not wrap the response in
  "assessment_draft", "assessment", "draft", metadata, title, role_title,
  seniority, language, or threshold_score.
- Every section must include title, description, duration_minutes, weight,
  sort_order, and questions.
- Every question must include type, prompt, expected_rubric, points,
  difficulty, and sort_order.
- type must be one of the allowed question type values from the input.
- difficulty must be one of: easy, medium, hard.
- Use 5 points for supporting questions, 10 for standard questions, and 20
  for questions with major hiring consequences.
- Every question must be open-ended and provide an expected_rubric.
- Prefer situational judgment, case analysis, work samples, behavioral
  evidence, prioritization, and communication simulations.
- Do not include additional properties anywhere in the JSON.

Keep the assessment review-friendly:
- Use clear section titles.
- Treat every entry under "existing_content_to_avoid" as an exclusion list of
  section and question content that is already present in the campaign.
- Before returning the draft, compare every proposed section and question
  against the complete exclusion list.
- Generate only net-new sections and questions with meaningfully different
  topics, scenarios, competencies, and evidence sought.
- Do not reuse or closely paraphrase an existing section title, section
  description, question prompt, scenario, or expected rubric.
- When "existing_content_to_avoid" is empty, generate the assessment normally.
- Match the requested language, difficulty, and question mix.
- Prefer concise rubrics that describe observable qualities in strong answers.
- Do not generate trivia or prompts with a fixed correct answer.

Output only structured JSON that matches the exact schema above.
